# 推导式图解课程 Skill（V2.0）

设计原则：概念列表、箭头流程、外链和滑块**不能**单独构成深度课程。默认阅读页应当让学习者不用离站就能推导一个具体机制。

1. **先确定对象和不变量**：例如请求 ID、逻辑 KV 块、物理块、Tensor Shape、Warp 状态；禁止把物理数据与逻辑控制关系混为一谈。
2. **机制图表现身份和变化**：显示实际数据、地址、Tile、状态或时间线；同一对象保持一致标签和配色；必须写明教学假设和不模拟的系统部分。
3. **数学必须真实排版**：使用原生 MathML，不以普通文本中的 `a*b` 或未渲染 LaTeX 冒充公式。LaTeX/ASCII 可作为复制附件，但非主要展示。
4. **变量就地解释**：所有符号、索引、单位、约定要放在公式相邻的变量表；字节单位 B 与 Token Budget B 必须区分。
5. **必须有算得出来的例子**：至少三步（已知输入 → 中间数值 → 输出/边界），并用独立公式或参考实现检验。指明是否仅为教学数据。
6. **从机制导出权衡**：先展示为什么产生这个状态，再解释它解决什么性能问题和可能的反例；不反过来只写价值口号。
7. **保留深入入口**：原论文和官方源码是复核/扩展而非基础知识来源；版本依赖必须标注。
8. **不虚构实测**：任何 B200/自研芯片数据需明确公开来源或实验记录；内网秘密不进入公开仓库。
9. **移动端优先**：一屏一个问题和一张有实际对象的图，公式允许自身滚动、整页不得横向溢出；已有进度和课程 ID 不改变。
10. **质量标记不能虚假**：仍只有概览文字的章节必须显式提醒“尚缺机制级推导”，未做实测不能自称 L4 已完成。

验收：`node --test tests/*.test.mjs`，浏览器检查原生 MathML 布局和新旧进度，检查真实图与数值推导一致、公式变量全部定义。
