# 机制可视化与持续生长的知识图谱

本 Skill 是本仓库原创的内容与交互质量规范。参考源只作为设计原则，**未复制或直接安装第三方 Skill**。来源见 `docs/diagram-design-standards.md`。

## 核心原则：图必须比文字做得更多

合格的技术图，至少呈现文字难以清楚表达的 **空间、数量、身份、关系、状态变化、资源竞争、张量变换或因果权衡** 之一。

1. 先写一个 **可检验的问题**：用户操作图之后究竟理解什么，能预测什么？不是“看懂整个系统”。
2. 画的必须是机制本身，不能只画“为什么需要它”或把段落放进方框。画出**对象实例**：KV 页、Block Table 条目、Tensor Shape、实际数值、Warp Ready 状态、IR 的操作节点等。
3. 最少有两层视角：**总关系**与**一个可追踪对象**。缩放不是简单缩小所有文本；应切换抽象尺度。
4. 同一对象在视图之间必须有**稳定身份和颜色**，例如 A[0] → P3 → Refcount=2；用户选择时相关位置同时高亮。
5. 交互必须改变**机制的可观测状态**，而不仅仅改变一个倍数或把同样的文字换个标题。用户应能预测、操作、比较、核对。
6. 箭头必须有语义。区分**依赖、数据流、控制流、地址映射、资源共享**，不要用无标记线条表达模糊的“相关”。
7. 内容直接在本页讲清楚。外链只是**核对**与**深挖**。展示具体实例、反例、适用边界和版本限制，不只说“提升性能”。
8. 移动端应重新编排信息密度，不能把宽图整体压缩到 360px；可用分组和上下游局部图代替缩小原图。
9. 不要为了美观增加与问题无关的流光、渐变、动画。用户动作触发的动效只用于回答“究竟什么变了”。
10. 必须审校：**逻辑不变量测试 → 桌面/手机实际截图 → 阅读者是否能解释机制 → 无外链能否学习 → 原课程/进度不回退**。

## 一张图在发布前必须通过的四个问题

- **识别**：图里的对象是什么？输入/输出在哪？符号是否有定义？
- **演化**：点击下一步，具体哪个内存块、数值、依赖或计算结果发生了变化？
- **归因**：从图能判断一个推断的前提、因果路径和失败条件吗？
- **迁移**：可以跳转到哪条相关知识（为何相关），并将自己验证的新发现记录成带关系和证据的节点吗？

## 知识节点与边语义

- 六大领域不变。权威课程节点使用 `site/js/depth-content.js` 的稳定 ID。
- 新课题写入课程数据与审核过的 `curatedRelations`；每条边有 `from`、`to`、`type`、`why`，且 `why` 必须是可验证的机制解释，不是“二者都重要”。
- 学习者自己的见解通过 `site/js/semantic-graph.js` 的个人子图保存；不能无审批直接混入公开事实或用户个人进度。
- 新见解至少连接一个已有节点，保存理解/证据/验证状态；允许纠错、增加更多关系、删除。导出可独立审阅后再写入 GitHub。
- **明确区分已浏览、自评理解和经过实验证实**。用户自评验证不代表机构或课程已认证。

## 示范样板与审计不变量

**Paged KV Cache** (`site/js/kv-studio.js`)
- 保持逻辑块 → Block Table → 物理块映射与稳定身份；重放新增、共享、追加、释放、复用。
- 验证请求长度所需块数、共享物理块内容一致、引用数量和释放规则。固定 4-token 块仅为教学示意。
- 表示的是聚合 KV 状态，**不是把 Token 字符串存放到 GPU Cache**。

**Online Softmax** (`site/js/softmax-studio.js`)
- 展示一条 Query 行跨两个 KV Tile 的 m、l、a 更新。
- 若新的最大值上升，旧统计量必须进行指数重缩放。最终输出与直接 Softmax 数值一致。
- 不把单行示意当作完整 FlashAttention 或带宽 Benchmark。

## 第三方材料政策

优先参考原论文、官方图、公开代码，再针对本仓库用户的提问重新设计。要复用第三方图片时逐图确认许可证、署名、版本并写入 `docs/diagram-provenance.md`；不因“网上可见”就假定能直接复制。内部公司资料不得进入公开仓库。
