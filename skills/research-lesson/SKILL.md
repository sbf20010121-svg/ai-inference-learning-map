# 源码与事实先行的知识图谱课程

1. **先选择可验证的真实研究对象**，固定公开论文/官方文档/仓库提交。不要从几句简介直接生成课程。
2. 列出该对象的**输入、输出、变量 shape、状态、不变量、边界条件**。将性能假设与技术事实分离。
3. 建立可执行的极小数学模型；证明公式/顺序与所引用实现一致。对比不同机制时不得把 toy model 冒充生产 Kernel。
4. **图承担解释任务**：要让某个值、矩阵、状态、布局、控制依赖实际变化；只画方框和箭头不算图解完成。
5. **交互先提出预测，再给证据**：例如相同 Key 重写状态、两个 Chunk 的仿射组合、尾块 Mask 导致的有效索引变化。
6. 所有符号要在图旁就地解释；主要公式用原生 MathML 或经验证的数学排版；移动端不能强制整页横向滚动。
7. 代码部分区分：被核实的真实代码事实、重写的机制伪代码、真实机器产物。SASS、GPU 周期、寄存器占用不能凭想象生成。
8. 测试要包含**数学正确性 + 点击交互 + 无横向溢出 + 原有课程节点/进度兼容**；不要只校验页面有没有内容。
9. 把课程接回原六大领域稳定 ID；用户个人笔记保持私有，**绝不能把私人学习评价原文写入公开仓库**。
10. 发布时标记课程的真实完成状态和遗漏：研究依据、已验证数学、已检查页面、尚未完成的源码/硬件实测。
