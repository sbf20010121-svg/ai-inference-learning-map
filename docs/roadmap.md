# 学习与产品路线

## V1.1：已实现

- 六大模块保留原有知识结构；自研芯片微架构为平行深入线。
- 10 节可点击课程：全链路、Transformer 算子、vLLM、编译器、Pipeline、GPU Memory、Profiling、OS/Runtime、VLA、世界模型。
- 分步执行链路、学习目标、关键判断、单题理解检验、相关资料与课程连接。
- 参数实验：局部加速与总延迟、VLA 迭代、Prefill / Decode、Warp 等待。
- 本地进度及笔记 JSON 导入导出、深色模式、移动端目录、GitHub Pages workflow。

## V1.2：中文易懂、场景和知识关联优化（已实现）

- 首页增加 LLM / 机器人 VLA / 世界模型可交互学习场景，每一步对应技术领域、计算负载、性能指标及一节课程。
- 六大领域默认显示简洁主线图，深度模式仍可显示全部课程；系统基础以独立支撑层呈现。
- 每个模块、课程之间新增“为什么相关”的中文解释，不把连线当成因果关系的证据。
- 术语速查附中文说明和课程入口，界面标题改为中文优先。
- 移动端默认只显示六大领域，减少过长列表；课程与搜索仍可访问。

## 下一步（按学习价值排序）

1. **学习摸底与推荐路径**：由用户先回答若干简短诊断题，再给出跳过已掌握概念的建议；不能把判断题通过等同于实际工程能力。
2. **更具象的 GPU 动态示意**：指令时间线、Warp 调度、数据访存、计算/访存重叠。内容注明“教学抽象”或基于哪代公开硬件。
3. **模型算子 Profiling 实验记录**：加入可复制但不捏造结果的实验模板（Shape、dtype、warmup、同步、正确性、环境）。
4. **模型专项**：SmolVLA / openpi 的真实源码追踪、视频世界模型架构、VLA 专用 Action Expert 调用与调度。
5. **多设备进度同步**：若确实需要，可经明确授权把进度写回 GitHub 私有文件。当前不要引入后端。

## 特别不做

- 不从头重复完整 vLLM 初学者教程。
- 不以“学习 GPU”为由要求读取或同步企业内部文件。
- 不直接嵌入未知第三方脚本、远程 Agent 服务或无用的多 Agent 架构。
- 不把纯理论知识点堆叠成密集不可交互文章。

## V1.3：多专题纵深图谱（2026-11-07 已实现第一版）

- 顶层六大模块、10 节 L1 概览课和 3 个场景不变；新增「深度图谱」导航。
- 实际落地 **19 个二级专题**，覆盖模型/LLM/MoE/VLA/世界模型、推理引擎/PD/部署、编译器/Runtime、GPU Kernel、系统基础和 B200 微架构。
- 支持 **4 条跨领域串联路径**：LLM→GPU、推理部署与 PD 分离、Kernel→B200、机器人 VLA 与世界模型。
- 每个专题有 L2 的可点选机制/数据流图、L3 的官方资料与源码追踪入口、L4 的实验设计、判断题、关联知识与学习笔记。
- **13 个专题附带滑块计算器**：基于明确假设的 KV 传输/Cache、调度 Token 预算、Tile 网格、Amdahl 局部加速、动作迭代、世界模型 token 数等；均非硬件实测。
- 进度仍保存在浏览器，JSON 导出/导入包含原 L1 + 新增深度专题（兼容旧版本）。
- 独立维护 `skills/deep-topic-authoring/SKILL.md` 和 `tests/depth.test.mjs`，不改动原有学习进度 ID。

### 尚未完成、明确留待逐步验证

- L3 目前提供公开文档/源码入口与对应观察问题，**没有对所有框架版本逐函数、逐行审计**；来源或版本变化时需要重查。
- L4 的数学模型不能替代真实 GPU Benchmark；后续要添加真实数据记录与 Profiling 对照实验（不能公开任何企业内网资料）。
- 二级图谱目前是面向学习的目录、流程图和有说明的关联路径；不宣称已经建成完整 GPU 周期级仿真器。
- 未来结合用户实际学习反馈，扩充 MLA/低精度 KV/投机解码、更多算子/机器人世界模型，优化层级图与源码交互。

## V1.4：知识覆盖审计与证据实训

- 原六大模块与 19 个深度专题保留；不修改旧课程 ID 和既有学习记录。
- 新建 **77 项主流技能覆盖审计**（P0/P1/P2），明确标记「已有机制课」「只在关联课程涉及」「尚缺深度课程」。
- 加入 **5 个真正需要决策的教学案例**：vLLM Token Budget 逐轮重放、PD 分离方案判断、Profiler 证据归因与受控实验、从 FX 到 Fusion 的临时访存、VLA Action Chunk 异步执行时间轴。
- 所有实验结果按“教学假设”标注，不声称模拟真实 vLLM、B200 或机器人精确时延。老滑块模型变成可选的公式辅助工具，不当作独立实训。
- 自动测试新增覆盖数据一致性、请求重放、PD 权衡、融合读写量和异步动作播放；不将通过测试等同于实际硬件 Benchmark。

### 仍需重点建设

1. P0 未有独立深度课的 RoPE/Norm、推测解码、量化与低精度 Kernel（现在在覆盖审计里明确列出）。
2. P1 的 MLA、线性注意力/SSM、采样、编译/部署导出、功耗与系统运维。
3. 对关键框架版本固定 commit 的源码追踪，以及真实代码级 Kernel 映射。
4. 用开源可复现的工作负载替代教学假设的时间线；补正式实验环境/对照组/正确性与 P99 统计。
5. 适用范围：AI 模型推理、GPU 性能与机器人模型；不要求把全部 OS 内核或机器人本体学科塞进地图。

## 判断“课程是否完成”的标准

概念图能够正确定位 L1；组件数据/控制流解释机制 L2；固定版本源码、张量 Shape 和设备 Kernel 证据才算 L3 可验证；正确性、端到端性能、反例与可复现对照实验证据齐全才算 L4 实战。**本次增加的实训属于教学模拟，不是 L4 实测结论。**


## V1.4 第二轮补强（已实现）

- 原 19 个深度专题增加为 **25 个**，新增推测解码/MTP、量化/FP8/FP4、RMSNorm/RoPE/SwiGLU、MLA、线性注意力/SSM、vLLM/SGLang/TensorRT-LLM 对比。
- 77 项审计现为：**47 项有机制课、24 项仅部分涉及、6 项尚缺深度课**；所有 P0 项都有专题入口，但 8 个 P0 仍只在相关章节部分涉及，不能据此视为完全深入。
- 当前六项显式缺口：采样（Top-k/Top-p）、点云/3D、TensorRT/ONNX Engine、Gather/Scatter、容器与驱动部署、功耗/时钟/热稳定性。
- 下一阶段优先按使用频率补齐 Top-p 与 Gather/Scatter、TensorRT Engine 和正确性验证；其次用开源样例实现真实可执行源代码 Trace、设备 Kernel 对照，而非继续增加只有滑块的教学模型。
