## V1.3 设计目标：从知识地图深入到真实技术机制（规划中，尚未实现）

> 不改变 V1.1 / V1.2 的六大模块和原有节点。保留概念地图作为入口，对核心节点纵向增加 2–3 层可展开内容。无需把所有知识点写成完整教材。

### 统一深度结构
- **L1 全局认知**：在系统中处于哪里、解决什么问题、与其他模块的联系。沿用现有内容。
- **L2 工作机制**：系统结构图、控制流/数据流、关键公式及设计权衡，解释为什么这样工作。
- **L3 源码与 GPU 执行**：具体版本、源码路径及必要函数/关键张量 shape；从模块调用追踪到算子、Kernel / 编译路径与 GPU 指标。必须能够核实，不能编造源码位置。
- **L4 性能实验与优化**：可复现实验配置、正确性检查、端到端和关键路径指标、优化假设、正反例及瓶颈归因。实验数值没有实测时明确标注教学假设。

不是每个节点都强行达到 L4。核心方向至少覆盖 L3；GPU/Kernel/推理性能主线尽可能覆盖 L4；通用 OS 知识可按需停在 L2。

### 优先制作的六条纵深路径（按顺序）
1. **大模型计算与算子**：Transformer / GQA / MLA / MoE；Prefill-Decode 的张量维度、主要算子和算力/带宽特征；推导成本，再读 Kernel。
2. **推理引擎与部署**：vLLM V1 Scheduler、KV Cache 分配、Prefix Cache、Chunked Prefill、Model Runner；PD 分离、KV 传输、TP/EP、TTFT/ITL/吞吐/SLO；区分单实例调度与多实例 PD 分离。
3. **编译器与 Runtime**：PyTorch→图捕获/IR→Inductor/Triton→PTX/SASS 的一条具体路径；编译期与运行期边界、数据布局、寄存器、CUDA Graph、启动与同步。
4. **Kernel 与 GPU 微架构**：从 GEMM / Attention / Gather 选真实 shape 做 Profiling，逐层分析访存、流水线、Warp Stall、Occupancy、Roofline 与可解释的性能假设。
5. **VLA / 动作模型**：从真实开源模型追踪图像/语言/状态→Action Expert→Flow / Diffusion / Action Chunk，重点研究动作头与 LLM Decode 不同的计算形状及推理开销。
6. **世界模型**：视频/状态预测、时空注意力、生成迭代、缓存、数据搬运，解释与 VLA、机器人控制的关系；先做到 L2–L3，必要时再做实测。

### 每个核心深度专题的最小交付
- 可在总地图原有节点展开的**二级/三级子节点**，不新增顶层模块。
- 至少 **1 张机制图 + 1 张数据/控制流或时间线图**，图区分抽象示意与具体实现。
- 至少 **1 个可交互示例**：如调整 Batch/Sequence/Shape、KV 大小、动作迭代步数、带宽或关键路径占比，并展示前提与边界。
- **1 个公开源码或官方文档定位**，标注版本/提交，解释输入输出与张量形状。
- **1 个非记忆性理解题**与**1 个性能诊断/验证任务**；支持已掌握跳过、返回地图及跨章节关联。

### 首个完整样板：PD 分离（Prefill/Decode Disaggregation）
- L1：为什么拆分，单实例混合执行和两个专门实例有何差异。
- L2：Proxy → Prefill → KV Transfer → Decode 的控制流和数据流；先讲独立调参和尾延迟，再讲新增传输成本。
- L3：以固定版本 vLLM 官方文档/源码为准，定位 Scheduler、KV Connector、Worker；不要把所有网络/连接实现都说成同一种路径。
- L4：可调整请求输入/输出长度、并发、P/D 资源配比与传输带宽的教学实验；实测时比较 TTFT、ITL/P99、吞吐、GPU 利用率。明确“PD 分离并不必然更快”。
- 推荐参考：vLLM Architecture Overview 与 Disaggregated Prefilling 官方文档（功能可处于实验性阶段）。

### 实施原则
- 优先做 1–2 个达到 L4 的真实样板，再复制模板扩展其他章节。
- 不为追求“深”堆砌无法验证的讲解；以可解释的机制、可信源码和可复现实验为标准。
- 内容与呈现分离，深层节点可按需加载；适配移动端、保留中文讲解。
- 公开仓库不存放任何企业内网芯片架构、内部测试数据、内部源代码或可反推的私有参数。
