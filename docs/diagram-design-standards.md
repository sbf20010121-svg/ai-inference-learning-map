# 什么才是高质量技术机制图？——V1.8 视觉设计审计

## 用户目标和问题

这个网站的任务不是将教程组织成一个更好看的目录，而是让研究 GPU、推理系统、编译器和机器人模型的人**形成可复用的结构与推理能力**。前几版的问题是同形流程方框过多、图里没有可观察数据、点击不改变真实机制，用户需要穿梭多个页面才能找到完整解释。

## 研究过的公开参考（只学习设计方法，不复制外部代码）

1. [Anthropic Frontend Design Skill](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)：视觉结构承担信息含义；不要无差别重复带编号的卡片；图和动效应服务于信息识别，避免模板式网页外观。
2. [Transformer Explainer（Georgia Tech）](https://github.com/poloclub/transformer-explainer)：用户改变输入，可以沿着 Attention、层内计算及输出观察真实数值，且在不同抽象层之间切换。这说明“图”应该把数值/对象与计算联系起来，而不仅仅展示一个方框序列。
3. [Distill FAQ](https://distill.pub/faq/)：高质量静态图注重图形表达，动态机制使用可交互矢量图，重视来源和许可。
4. [React Flow 示例](https://reactflow.dev/examples/layout/expand-collapse)：完整图谱结构保留在数据中，界面按需折叠/展开，避免把所有节点同时塞进屏幕。收费示例仅作设计参考，本项目未直接使用其实现或许可限制内容。
5. [vLLM 原版 PagedAttention 介绍](https://vllm.ai/blog/2023-06-20-vllm)：逻辑 KV 块、Block Table 和非连续物理块是三个不可混淆的实体，适合跨层追踪同一映射。
6. [vLLM Paged Attention 内核文档](https://docs.vllm.ai/en/latest/design/paged_attention/)：内存映射和实际 Attention Kernel 的数据布局/加载是不同层面的概念，不能用一个“箭头”声称复现整个实现。

## 改造决定

- 保留 V1.7 专注阅读器和原六大领域，不增加新的首页长列表。
- 新增独立「知识网络」视图：中心聚焦一个知识点，只画一跳的**具体关系类型**，下方逐条解释连线原因。可由搜索、正式课程及个人学习见解延伸；不是自由连线的静态思维导图。
- 新增 **Paged KV Cache** 的内存身份图：同一物理块在共享状态始终高亮相同 ID，Block Table、逻辑块、物理块同步显示。
- 新增 **Online Softmax** 的数值图：一个 Query 行，四个 score 分成两个 Tile，读第 2 个 Tile 时显示旧统计量如何缩放，并与直接 Softmax 核对。
- 自定义知识记录默认“待验证”，用户编辑、自评、关联及删除皆留在本地；导出与旧课程进度兼容。真正写入公开仓库前需要技术审核。

## 发布验收（不看图的数量）

| 评审维度 | 不合格 | 合格 |
|---|---|---|
| 对象 | 只有“调度 → 优化”标题 | A[0]、P3、refcount 等可识别实体 |
| 映射 | 箭头只是“相关” | Block Table A[0] → P3；边有明确关系类型和原因 |
| 数值 | 调倍数以后显示新数字 | 第 2 个 Tile 改变 m，旧统计量乘 exp(oldM-newM) |
| 错误边界 | 展示“必然更快” | 仅声明机制示意，不伪称真实性能结果 |
| 持久性 | 看完就丢失 | 可增删改查个人见解、明确证据、导出 JSON |
| 可访问性 | 手机缩小全图 | 手机按逻辑/物理结构重新布局，不丢掉交互 |
