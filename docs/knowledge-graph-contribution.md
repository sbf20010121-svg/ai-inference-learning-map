# 知识图谱持续生长：贡献、验证与版本维护

## 目标

原有六大领域与课程仍是稳定导航。真正可延伸的知识图谱由**节点（概念/机制/学习见解）+ 有类型的关联 + 连接原因 + 证据与验证状态**组成。

## 数据层

- `site/js/depth-content.js`：维护的 25 个公开课程主题，ID 长期稳定。
- `site/js/semantic-graph.js`：公开审核过的关系（有类型与具体说明）及个人子图合法性检查。
- 浏览器 `localStorage` 的 `ai-inference-semantic-graph-v1`：用户个人节点、关系和学习状态。自动与顶部「导出进度」合并；不会自动同步设备。
- 上传之前从网站导出 JSON，可作为 ChatGPT/GitHub 修改提案；公开项目提交只能在用户确认保密和证据后进行。

## 节点结构（示意）

```json
{
  "id": "mine-<unique-id>",
  "title": "共享前缀可减少重复 KV",
  "summary": "逻辑块 0 与 B 的逻辑块 0 指向同一物理块，在满足复用条件的情况下只存一份已填满的前缀。",
  "module": "engine",
  "status": "not-verified",
  "source": "https://vllm.ai/blog/2023-06-20-vllm"
}
```

关系结构：`{id,from,to,type,why,origin}`。类型为 `prerequisite` / `produces` / `accesses` / `implements` / `explains` / `contrasts` / `extends`。`why` 必须写清具体机制，不接受“两个都很重要”。

## 读懂或修改新知识的流程

1. 在原课程或实验里形成一个可解释的具体观察。
2. 点击「知识网络」选择已有锚点。用自己的话写下机制，选择真实关系类型并写明连接依据。
3. 在图谱中看清上下游，若原先理解错误则修改或删除，而不是留下互相矛盾的卡片。
4. 用公开资料/源码/实验结果核对后自评验证；**自评状态不等于自动经过技术审核**。
5. 导出 JSON 备份，可交给 AI 整理和技术审查，再选择把适合公开的新课程写入 GitHub。公开仓库不自动接收公司内部事实。

## 后续开发方向

- 增加多跳图谱查询和证据版本记录；避免为了可视化强制显示全局“毛线团”。
- 支持一次学习后自动形成**待审核建议**，由学习者确认、再归档，而非将 LLM 猜测直接作为可靠节点。
- 提供实验记录 Schema：硬件/软件版本、Shape/dtype、Bench/Trace、正确性/误差、推断边界，并与图谱中的性能因果链接。
- 真正跨设备同步需要认证和安全存储；静态 GitHub Pages 不适合在前端放写入个人仓库的 Token。
